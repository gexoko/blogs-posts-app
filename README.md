# Blogs and Posts API

Учебный REST API для управления блогами и постами. Поддерживает создание, чтение, обновление и удаление ресурсов, валидацию входных данных и Basic Auth для операций изменения.

## Технологии

- Node.js, TypeScript и Express 5.
- express-validator — валидация запросов.
- Jest, ts-jest и Supertest — тестирование API.
- OpenAPI 3, swagger-jsdoc и swagger-ui-express — документация.
- ESLint и Prettier — проверка и форматирование кода.

Данные хранятся в массивах в памяти процесса, без внешней базы данных. При перезапуске изменения теряются и загружаются начальные записи из `src/db/in-memory.db.ts`.

## Локальный запуск

Нужны Node.js версии 24 или выше и установленный pnpm. В репозитории используется `pnpm-lock.yaml`.

Установите зависимости из корня проекта:

```bash
pnpm install --frozen-lockfile
```

В первом терминале запустите компиляцию TypeScript:

```bash
pnpm watch
```

Дождитесь первой успешной компиляции. Во втором терминале запустите сервер:

```bash
pnpm dev
```

Команда `watch` создаёт JavaScript-файлы в `dist`, а `dev` запускает `dist/index.js` через nodemon с включённым отладчиком Node.js.

- [Проверка доступности](http://localhost:5001/) — ответ `Hello world!`.
- [Список блогов](http://localhost:5001/ht_02/api/blogs).
- [Список постов](http://localhost:5001/ht_02/api/posts).
- [Swagger UI](http://localhost:5001/api/).

## Настройки и авторизация

Настройки читаются из `process.env` в `src/settings/config.ts`.

| Переменная       | По умолчанию | Назначение              |
| ---------------- | ------------ | ----------------------- |
| `PORT`           | `5001`       | Порт локального сервера |
| `ADMIN_USERNAME` | `admin`      | Логин администратора    |
| `ADMIN_PASSWORD` | `qwerty`     | Пароль администратора   |

Автоматическая загрузка `.env` не настроена. Переменные можно задать в оболочке перед запуском. Пример для PowerShell:

```powershell
$env:PORT = '5001'
$env:ADMIN_USERNAME = 'admin'
$env:ADMIN_PASSWORD = 'your-password'
pnpm dev
```

GET-запросы блогов и постов публичные. Для POST, PUT и DELETE этих ресурсов нужен заголовок:

```text
Authorization: Basic <base64 от строки username:password>
```

В Swagger UI учётные данные вводятся через **Authorize**. Неверные или отсутствующие данные возвращают `401 Unauthorized`.

## Эндпоинты

Базовый путь ресурсов — `/ht_02/api`. Сам этот путь не имеет отдельного обработчика.

| Метод  | Путь                          | Назначение                 | Basic Auth | Успешный ответ |
| ------ | ----------------------------- | -------------------------- | ---------- | -------------- |
| GET    | `/ht_02/api/blogs`            | Список блогов              | Нет        | `200`, массив  |
| GET    | `/ht_02/api/blogs/:id`        | Блог по ID                 | Нет        | `200`, объект  |
| POST   | `/ht_02/api/blogs`            | Создать блог               | Да         | `201`, объект  |
| PUT    | `/ht_02/api/blogs/:id`        | Обновить блог              | Да         | `204`          |
| DELETE | `/ht_02/api/blogs/:id`        | Удалить блог               | Да         | `204`          |
| GET    | `/ht_02/api/posts`            | Список постов              | Нет        | `200`, массив  |
| GET    | `/ht_02/api/posts/:id`        | Пост по ID                 | Нет        | `200`, объект  |
| POST   | `/ht_02/api/posts`            | Создать пост               | Да         | `201`, объект  |
| PUT    | `/ht_02/api/posts/:id`        | Обновить пост              | Да         | `204`          |
| DELETE | `/ht_02/api/posts/:id`        | Удалить пост               | Да         | `204`          |
| DELETE | `/ht_02/api/testing/all-data` | Очистить все блоги и посты | Нет        | `204`          |

Ответ `204` не содержит тела. Служебный маршрут `testing/all-data` удаляет все текущие данные и используется тестами; начальные записи он не восстанавливает.

## Формат данных

Запросы с телом используют `Content-Type: application/json`. Объекты передаются без обёрток `data` и `attributes`. ID в ответах — строки.

### Блог

Тело POST и PUT:

```json
{
  "name": "Gexodus",
  "description": "Блог о разработке",
  "websiteUrl": "https://example.com"
}
```

Ответ при создании и получении содержит эти же поля и строковый `id`.

### Пост

Тело POST и PUT:

```json
{
  "title": "Первый пост",
  "shortDescription": "Коротко о проекте",
  "content": "Создаём API блогов и постов.",
  "blogId": "1"
}
```

Пример ответа:

```json
{
  "id": "4",
  "title": "Первый пост",
  "shortDescription": "Коротко о проекте",
  "content": "Создаём API блогов и постов.",
  "blogId": "1",
  "blogName": "Gexodus"
}
```

При создании и обновлении поста указанный блог должен существовать. `blogName` берётся из найденного блога, включая случай смены `blogId`. Переданные клиентом `id` и `blogName` игнорируются.

## Валидация и ошибки

Все поля входной модели обязательны для POST и PUT. У текстовых полей удаляются пробелы по краям, затем проверяются непустое значение и длина.

| Ресурс | Поле               | Ограничения текущей реализации                            |
| ------ | ------------------ | --------------------------------------------------------- |
| Блог   | `name`             | Строка, от 1 до 15 символов                               |
| Блог   | `description`      | Строка, от 1 до 500 символов                              |
| Блог   | `websiteUrl`       | Строка до 100 символов; HTTPS-адрес по шаблону валидатора |
| Пост   | `title`            | Строка, от 1 до 30 символов                               |
| Пост   | `shortDescription` | Строка, от 1 до 100 символов                              |
| Пост   | `content`          | Строка, от 1 до 100 символов                              |
| Пост   | `blogId`           | Числовая строка с ID существующего блога                  |

Точный шаблон `websiteUrl` приведён в Swagger. Он допускает не все возможные URL: например, адреса с query-параметрами не проходят текущую проверку.

При ошибках валидации возвращается `400` и не более одной ошибки на поле:

```json
{
  "errorMessages": [
    {
      "field": "blogId",
      "message": "Blog not found"
    }
  ]
}
```

Другие основные статусы: `401` при неверной авторизации и `404` при отсутствии ресурса. Формат тела ошибки зависит от операции и описан в Swagger.

## Проверки и команды

```bash
# Все тесты API
pnpm jest

# Тесты с отчётом покрытия
pnpm jest:coverage

# Проверка типов без генерации файлов
pnpm exec tsc --noEmit

# ESLint без автоматических исправлений
pnpm exec eslint .
```

Тесты запускают Express через Supertest локально, без обращения к Vercel. Проверяются CRUD, валидация, авторизация, запрет подмены служебных полей и связь постов с блогами. Перед каждым тестом очищается локальное тестовое хранилище.

Команды `pnpm lint` и `pnpm format` изменяют файлы: первая запускает ESLint с `--fix`, вторая — Prettier с `--write`.

## Структура проекта

```text
src/
  index.ts          # Запуск сервера
  setup-app.ts      # Подключение middleware, роутеров и Swagger
  auth/             # Basic Auth
  blogs/            # DTO, роутер, handlers, репозиторий, валидация и документация блогов
  posts/            # DTO, роутер, handlers, репозиторий, валидация и документация постов
  core/             # HTTP-статусы, обработка ошибок и настройка Swagger
  db/               # Данные в памяти
  settings/         # Настройки окружения
  testing/          # Очистка данных
__tests__/
  e2e/              # Проверки HTTP API
  utils/            # Подготовка данных и вспомогательные функции
```

Роутеры задают цепочки middleware и обработчиков. Валидаторы проверяют запросы, handlers формируют HTTP-ответы, репозитории работают с данными, а мапперы преобразуют внутренние сущности в модели ответа.

## Swagger

Документация доступна по `/api/`. `swagger-jsdoc` собирает файлы `src/**/*.swagger.yml`, а `swagger-ui-express` показывает интерактивную страницу. Общие схемы находятся в `src/core/swagger/openapi.swagger.yml`, описание блогов и постов — в папках `docs` соответствующих модулей.

Запускайте приложение из корня проекта: путь поиска YAML-файлов задан относительно текущего каталога.

## Развёртывание на Vercel

В `vercel.json` точкой входа указан `src/index.ts`; запросы направляются в Express через `@vercel/node`. Переменные окружения опубликованного приложения задаются в настройках проекта Vercel.

- [Опубликованный API блогов](https://blogs-posts-app-git-main-gexod.vercel.app/ht_02/api/blogs).
- [Опубликованный API постов](https://blogs-posts-app-git-main-gexod.vercel.app/ht_02/api/posts).
- [Swagger UI](https://blogs-posts-app-git-main-gexod.vercel.app/api/).

Доступ к адресам зависит от настроек Deployment Protection. Авторизация Vercel и Basic Auth приложения — отдельные механизмы.

In-memory-хранилище предназначено для учебных проверок: после нового запуска экземпляра на Vercel данные могут сброситься, а разные экземпляры могут содержать разные записи.
